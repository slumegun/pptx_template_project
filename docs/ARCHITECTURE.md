# Как устроен Лукас

Коротко: код делает всё, что можно проверить точно (разбор шаблона, лимиты, сборку PPTX, проверку вёрстки), а модели — то, что требует понимания текста и картинки (план, формулировки, критика).

## Части системы

- **frontend/** — React-интерфейс: загрузка шаблона, задание, прогресс, сравнение трёх вариантов, аудит, правка слайда.
- **backend/app/** — FastAPI. Хранит пользователей, шаблоны, запуски и версии в базе (SQLite или PostgreSQL), файлы — на диске. Долгие задачи уходят в очередь: Redis + RQ в Docker, фоновый поток при локальном запуске.
- **backend/engine/** — вся генерация: разбор шаблона, агенты, сборка, проверки, экспорт.

## Путь от шаблона до файлов

### 1. Подготовка шаблона (один раз)

`engine/ingest.py` читает PPTX и для каждого текстового объекта записывает:

- координаты, шрифт, кегль, цвет, выравнивание — так, как их реально нарисует PowerPoint, с учётом наследования от макета, мастера и темы;
- сколько символов туда помещается: по длине образца в шаблоне и по реальной ширине букв шрифта;
- колонку маркеров (галочек, точек, иконок, номеров) рядом с текстовым блоком — каждый маркер становится отдельным местом для пункта;
- ширину, до которой может вырасти рамка без переноса строк (узкий заголовок «Кейс» не должен превращать заголовок в «Упр.»).

`engine/fields.py` рендерит шаблон без текста и по пикселям находит свободную часть каждого поля: где нет картинок, линий и карточек.

Модель Template Analyst смотрит на превью слайдов и помечает объекты: логотип, иконка, место под текст, старый контент под удаление. Результат кэшируется по хешу файла.

### 2. Генерация (лимит около 5 минут)

1. **Факты.** Бриф и загруженные файлы (TXT, MD, CSV, JSON, PDF с текстом, DOCX) режутся на факты с указанием источника.
2. **План.** Deck Planner выбирает заголовки слайдов и факты для каждого.
3. **Макеты.** Для каждой из трёх тем код подбирает слайды шаблона (`choose_compositions` в `renderer.py`):
   - «Базовая» — макет, у которого число мест ближе всего к числу мыслей на слайде;
   - «Больше текста» — самые вместительные макеты, повторять их можно;
   - «Больше визуала» — макеты с иконками, галочками и параллельными пунктами.
4. **Текст.** Slide Worker пишет каждый слайд под места выбранного макета. Он получает лимиты символов, тип каждого места (пункт у галочки, строка списка, текстовый блок) и цель темы. Если ответ не влезает, сокращает слова точкой или оставляет галочки пустыми, он получает замечание и пишет ещё раз.
5. **Критика.** Deck Critic проверяет, что всё опирается на факты. Prompt Critic — что выполнено задание пользователя. Слайды с серьёзными замечаниями переписывает Slide Repair.
6. **Визуал.** Для темы «Больше визуала» Infographic Designer выбирает, какие слайды превратить в схему, плитки с крупными цифрами или график. Числа для графиков ищет код (`engine/visuals.py`), и только в уже проверенном тексте.
7. **Сборка.** `renderer.py` копирует слайды шаблона и вписывает текст в его же объекты, сохраняя стиль. Графики и таблицы — нативные, их можно править в PowerPoint.
8. **Экспорт и проверка.** LibreOffice делает PDF, Poppler — картинки, из них собирается HTML. Потом идут проверки (ниже). Visual Critic сравнивает каждый слайд с исходным макетом, и найденное отправляется на ремонт, пока хватает времени.

## Модели

Все вызовы идут через OpenRouter, один ключ на сервере. Модели открытые, до 35B параметров, лицензия Apache 2.0.

| Роль | Модель |
| --- | --- |
| Template Analyst | qwen/qwen3-vl-32b-instruct |
| Deck Planner, Slide Worker, Infographic Designer, Slide Repair | qwen/qwen3.8-27b |
| Deck Critic, Prompt Critic, Visual Critic | google/gemma-4-31b-it |

Поменять модель роли можно переменной `MODEL_<РОЛЬ>` в `.env`. Список разрешённых моделей — в `engine/model_registry.py`. Промпты лежат в `engine/prompts/`.

У шлюза (`engine/provider.py`) общий лимит параллельных запросов, лимит запросов в минуту, таймауты и ограниченные повторы. Закончился баланс — новые запросы в этом задании не отправляются, запуск можно повторить после пополнения.

## Проверки

Проверки — код, а не модель: они точные и бесплатные.

- **Вёрстка по PDF** (`rendered_audit.py`): текст не выходит за рамку, не наезжает на другой текст и картинки, весь текст из PPTX есть в PDF.
- **Шрифты** (`audit.font_issues`): гарнитура и кегль совпадают с шаблоном, шрифты встроены в PPTX.
- **Дизайн** (`design_audit.py`): цвета из палитры шаблона, контраст текста не ниже 4.5:1, выравнивание по направляющим, поля, растянутые картинки, сдвинутый логотип, заполненность слайда, подписи осей у графиков.
- **Содержание** (`audit.py`): остатки текста шаблона и заглушки, числа без опоры в фактах, пустые слайды, повторы.

Замечание бывает блокирующим или предупреждением. Часть замечаний исправляется автоматически по кнопке в интерфейсе, остальные — правкой слайда.

## Что не умеет

- PDF без текстового слоя (сканы) — OCR нет.
- SmartArt и сложные группы объектов в шаблоне воспроизводятся не полностью.
- CSV для графика — до 12 строк и 3 числовых столбцов.
- Лимиты символов — оценка. Редкий слайд всё равно может не влезть, тогда это покажет аудит.
