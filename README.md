# Лукас — презентации по вашему шаблону

Загружаете корпоративный шаблон PPTX, пишете, о чём должна быть презентация, и получаете три готовых варианта в PPTX, PDF и HTML. Текст в PPTX обычный, редактируемый, графики тоже. Дизайн берётся из вашего шаблона: шрифты, цвета, сетка и логотипы остаются на своих местах.

## Три варианта

Каждый запуск делает три версии одной презентации с одинаковыми фактами:

- **Базовая** — обычная подача: для каждого слайда выбирается самый подходящий макет шаблона.
- **Больше текста** — макеты, в которые помещается больше всего текста, и развёрнутые формулировки.
- **Больше визуала** — макеты с иконками и галочками, схемы, плитки с крупными цифрами и графики. График строится, только если числа есть в вашем тексте: мы их не придумываем.

## Как это работает

1. **Разбор шаблона.** Один раз на шаблон: код находит на каждом слайде места для текста, их шрифт и лимит по длине, списки с галочками, свободную зону каждого поля. Модель с компьютерным зрением помечает, что на слайде логотип, что иконка, а что старый контент, который надо убрать.
2. **План.** Модель раскладывает тему и материалы по слайдам. Каждый слайд опирается на конкретные факты из брифа или файлов.
3. **Текст.** Для каждой темы подбираются свои макеты, и отдельные модели пишут текст слайдов ровно под места этих макетов: не длиннее, чем помещается, по пункту на каждую галочку.
4. **Критики.** Одна модель проверяет, что нет выдуманных фактов, другая — что выполнено всё, что просили в задании. Если есть проблемы, слайды переписываются.
5. **Сборка и проверка.** PPTX собирается из слайдов шаблона. LibreOffice делает из него PDF, и код по готовому PDF проверяет каждую букву: не вылез ли текст за рамку, не наехал ли на картинку, тот ли шрифт. Последней смотрит визуальная модель и сравнивает слайд с оригиналом шаблона.

Подробнее — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Что нужно

- Ключ [OpenRouter](https://openrouter.ai) с балансом: все модели вызываются через него.
- Для Docker: Docker с Compose.
- Для локального запуска: Python 3.11+, Node 20+, LibreOffice (с Impress) и Poppler.

## Запуск в Docker

```bash
# впишите OPENROUTER_API_KEY в .env
docker compose up --build
```

Интерфейс откроется на http://localhost, API — на http://localhost/api, документация API — на http://localhost/api/docs.

## Локальный запуск

Бэкенд (база SQLite, очередь внутри процесса, Redis не нужен):

```bash
cd backend
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -e ".[test]"
# впишите OPENROUTER_API_KEY в backend/.env
uvicorn app.main:app --reload --port 8001
```

Фронтенд в соседнем терминале:

```bash
cd frontend
npm ci
npm run dev
```

Откройте http://localhost:5173. Dev-сервер проксирует `/api` на порт 8001.

На Ubuntu LibreOffice и Poppler ставятся так: `sudo apt install libreoffice-impress poppler-utils`. Пакета `libreoffice-core` мало: без Impress LibreOffice не открывает PPTX.

## Ключ API

Настройки уже лежат в репозитории: `.env` в корне для Docker и `backend/.env` для локального запуска. Впишите свой ключ OpenRouter в строку `OPENROUTER_API_KEY=` в нужном файле, и проект запустится.

Если вписываете ключ в публичный репозиторий, заведите для него отдельный ключ с лимитом трат в настройках OpenRouter: публичные ключи находят боты.

## Основные настройки

Все настройки лежат в `.env` (Docker) и `backend/.env` (локальный запуск).

| Переменная | Что делает |
| --- | --- |
| `OPENROUTER_API_KEY` | ключ OpenRouter, без него генерация не запустится |
| `MODEL_*` | какая модель отвечает за какую роль, лимиты запросов и таймауты |
| `AYA_DATABASE_URL` | база: SQLite для локального запуска, PostgreSQL в Docker |
| `AYA_LOCAL_JOBS` | `true` — задачи выполняются в процессе API, без Redis |
| `AYA_STRICT_TEMPLATE` | `1` — текст пишется строго в места шаблона (по умолчанию) |
| `AYA_FONT_DOWNLOAD` | `1` — докачивать открытые шрифты шаблона из Google Fonts |

## Структура

```
backend/
  app/        FastAPI: API, авторизация, очередь задач, хранилище файлов
  engine/     разбор шаблона, агенты, сборка PPTX, проверки, экспорт
  alembic/    миграции базы
  scripts/    проверка моделей и сквозной прогон API
frontend/     интерфейс на React + Vite
docs/         архитектура и описание API
examples/     пример брифа и CSV с данными
compose.yaml  Docker: база, Redis, API, воркер, веб-сервер
```

## Тесты

```bash
cd backend
pytest -q
```

Тесты не ходят в сеть и не тратят деньги: ответы моделей в них подменяются. Для части тестов нужен LibreOffice. Платная проверка всех моделей запускается только явно: `python scripts/check_models.py --live`.
